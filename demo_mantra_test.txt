# Regression for "Crash when using a mantra": handle_mantra_chant
# (player.c, the "Chant the mantra" feature) crashed with a SIGSEGV
# inside ce_strcmp on every single invocation, regardless of what the
# player typed -- two locals (_strupr's and get_message_string's
# return values) were `undefined4` (32-bit), truncating their real
# 64-bit pointer returns before ce_strcmp ever saw them. Fixed by
# giving them proper `char *` locals.
#
# Uses the CALLMANTRA demo command (calls handle_mantra_chant()
# directly) rather than navigating to and right-clicking one of the
# in-world mantra statues (confirmed present via SCANOBJTYPE/FINDOBJ at
# object type 0x157, e.g. level 1 tile (46,18)) -- this exercises the
# exact same crashing code path (the text-entry prompt and the
# known-mantra-string-table matching loop) without depending on
# dungeon navigation. Three invocations: a real matching mantra word
# ("RA", id 0x33), a "class" mantra ("SUMM RA", id 0x4a, the multi-skill
# dispatch branch), and a non-matching word -- all three reached the
# crashing comparison before the fix.
#
# Run with:
#   UW_ENABLE_3D_GEOMETRY=1 UW_FAST_SLEEP=1 UW_DATA_DIR="$(pwd)/data" \
#     UW_DEMO_FILE=demo_mantra_test.txt ./build/uw_dbg
