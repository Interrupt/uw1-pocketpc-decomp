KEY STATE
  DAT_0008697c[0..2]   swept X, Y, foot Z (1/8-tile units)   [foot Z also read as
                        *(short*)((char*)DAT_0008697c + 4) -- byte offset, == [2]]
  DAT_00086980/82/84   X / Y / Z sub-unit accumulators
  DAT_0008698a         signed vertical velocity for the sweep (+/-0x800 seed)
  DAT_0020488a         "vertical motion active" flag (= *(DAT_00204874+10)); gates gravity
  _DAT_000869a1        vertical rate (gravity accel / climb speed), per sweep,
                        derived from DAT_0020488a in movement_sweep_setup
  _DAT_0008699b        target surface height (floor when falling, ceiling when rising)
  DAT_00086990         sub-step count for the tick (= horizontal distance / 0x2000)
  DAT_00086992         horizontal step magnitude remainder
  DAT_002049d8/d9      destination tile floor height (envelope)
  DAT_002049d4 & 4     "walkable / auto-stick floor" -> step resolver snaps instantly
  byte DAT_00204874+0x26  player height (head clearance)
  byte DAT_00204874+0x27  step up/down limit
  byte DAT_00204874+0x25  wall-vs-step threshold
  DAT_0008699f/869a0   ceiling clearance (CONCAT11) for the head-fits test

WHY A DROP IS ONE TICK, NOT SMOOTH GRAVITY
  Vertical integration (FUN_0005a348: accel by _DAT_000869a1*0x20 per sub-step,
  land via FUN_00059d20) only runs when DAT_0020488a != 0. movement_sweep_setup
  returns early (DAT_0008698a = 0) whenever the vertical-velocity input
  psVar11[2] (== DAT_0020488a) is 0, and never computes _DAT_000869a1.
  The game only sets DAT_0020488a for scripted vertical motion -- jump,
  knockback, slope steps (via FUN_0005989c). Plain "walked off a ledge" never
  sets it. So no gravity accumulates; instead sweep_collision_flags' step
  resolver (LAB_0005a970) hits the `DAT_002049d4 & 4` clause and snaps the
  foot straight onto the lower floor in the single tick that crosses the edge.
  A real multi-tick fall would need: when the foot ends a tick more than the
  step-down limit above DAT_002049d9, set DAT_0020488a (downward) so the next
  ticks run FUN_0005a348 until FUN_00059d20 lands.

  called sweep_integrate_substep() with Ghidra-dropped args -- the vertical
  integrator ran with a garbage direction/scale. Now both forward param_1.
